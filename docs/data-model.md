# QuoteKai Data Model

**Document Version:** 1.0
**ORM:** Prisma
**Database:** PostgreSQL 16

---

## Schema Overview

The data model is intentionally minimal — a single `Quote` table. The point of this project is infrastructure, not data modeling.

---

## Prisma Schema

Location: `apps/api/prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Quote {
  id        String   @id @default(uuid())
  text      String
  author    String
  createdAt DateTime @default(now()) @map("created_at")

  @@map("quotes")
  @@index([createdAt(sort: Desc)])
}
```

---

## Field Notes

### `id`

- Type: `String` (UUID)
- Generated by Prisma using `@default(uuid())`
- Used as the primary key
- Used as the cache key suffix in Redis (e.g., when storing highlight metadata)

### `text`

- Type: `String` (varchar, no length limit at DB level)
- The actual quote content
- Should be kept under 500 characters for UI reasons (not enforced at DB)

### `author`

- Type: `String`
- Attribution for the quote
- May be `"Unknown"` for proverbs

### `createdAt`

- Type: `DateTime`
- Defaults to insertion time
- Mapped to `created_at` column (snake_case in DB, camelCase in code)
- Indexed for `ORDER BY` performance on the quote list query

---

## Index Strategy

One index: `(createdAt DESC)` to support the main query:

```sql
SELECT * FROM quotes ORDER BY created_at DESC LIMIT 200;
```

This is the query underlying `GET /api/quotes`. With the index, it's fast regardless of table size.

No other indexes needed for this project.

## Seed Data

The database is seeded on first deploy with approximately 100 quotes.

Seed script location: `apps/api/prisma/seed.ts`

The seed script:

1. Connects to the database
2. Truncates the `quotes` table (idempotent — safe to re-run)
3. Inserts 100 quotes from a hard-coded array (or a JSON file)
4. Logs the count

To run:

```bash
pnpm db:seed
```

Configured via `package.json`:

```json
{
  "prisma": {
    "seed": "tsx prisma/seed.ts"
  }
}
```

### Where to source quote data

Options:

- **Hand-curated:** write your own list of 50-100 favorite quotes
- **Public dataset:** download from a public quotes API or GitHub repo
- **Generated:** use a script to fetch from quotable.io or similar API once, save as JSON

Any approach is fine. Make sure the data is committed to the repo so seeds are reproducible.

## Migrations

Migrations are managed by Prisma:

```bash
# Create a new migration based on schema changes
pnpm db:migrate:dev --name <migration-name>

# Apply pending migrations (used in production)
pnpm db:migrate:deploy

# Reset the database (dev only, destroys all data)
pnpm db:migrate:reset
```

Migration files are committed to git under `apps/api/prisma/migrations/`.

---

## Migration History (Expected)

For this project, you'll have only one migration:

1. **`init`** — creates the `quotes` table with the `created_at` index

That's it. The schema doesn't evolve during this project.

---

## Why So Simple?

A single table is enough to demonstrate every caching pattern this project needs. Adding more tables (categories, tags, users, favorites) would distract from the infrastructure focus.

## Connection Management

In `apps/api/src/lib/prisma.ts`:

```typescript
import { PrismaClient } from "@prisma/client";

export const prisma = new PrismaClient({
  log: ["error", "warn"],
});

// Graceful shutdown
process.on("beforeExit", async () => {
  await prisma.$disconnect();
});
```

In `apps/worker/src/lib/prisma.ts`, the same setup. Each process gets its own Prisma client instance — connection pooling is per-process.

For this scale, default connection pool settings are fine. Prisma's default is 2× the number of CPU cores.

## Database URL Format

```
postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public
```

Examples:

```bash
# Local (Docker)
DATABASE_URL=postgresql://quotekai:quotekai_dev@localhost:5432/quotekai?schema=public

# Railway production
DATABASE_URL=postgresql://postgres:xxx@xxx.railway.internal:5432/railway?schema=public
```

Railway provides the URL automatically via its internal networking when services are linked.

---

## Backups

For this practice project: **no automated backups**.

Railway provides daily snapshots on paid plans, but for a practice project with no important data, this is unnecessary. If the database is lost, just re-run the seed.
